## 4. What the end theorems state and assume

- `<id>_spec : Spec zesuImage entry bound Pre Post`: every machine at the entry satisfying
  `Pre` reaches, within `bound` instructions of `next`, a state with `Post` (return, frame,
  result relation). `<id>_sail`: the same in the Sail model via `Rel`, `SailReaches`.
- Sail model: S1 top rung (config + specialise patches), regenerated by Nix with the stock
  Sail compiler; configuration accepted by the model's own validator. Class R hunks hold only
  on states satisfying invariants I1–I6 (`Configured`); no Lean proof relates patched and
  unpatched models.
- `ziskMemcpy` is the one trusted ZisK definition (memcpy runs as a 3-instruction service).
- `AllocAssumptions` (abstract heap `Heap L m`, allocator memory `Priv L`, alloc/free
  contracts) is an explicit hypothesis of F1/F4/F5, never an axiom.
- The machine faults on misaligned multi-byte accesses (the ELF allows them); none occur.
- The input region is plain read-only memory.
- Non-vacuity of F1/F4/F5 `Pre` is conditional on the abstract heap (see STATEMENTS.md).

## 6. Fallbacks and deviations

- `/usr/bin/time` absent: nixpkgs `time-1.10`.
- `bv_decide` banned (adds native axioms); replaced in executor and in 9 BinaryFv sites.
- `run_sound` takes `RodataLoaded` and also concludes a memory frame; `step` requires `pc % 4 = 0`.
- Landing-pad hunks reclassified R (invariant I5), `translateAddr` needs I6.
- F2 loops use a counted rule instead of `Reaches.loop` (tight bound 75 vs ~117).
- F3/F6 build a fresh symbolic state at each return point (callee writes inside the caller frame).
- Image extended with rodata `0x80114fb8:80`, `0x801152b0:16` for F6.
- Engine A zero-initialises 14 registers the generated model never initialises.

## 7. Rest of the ELF

- Compressed instructions (19 in `.text`): new decoder cases + Sail fetch of 2-byte words.
- CSR instructions (~7,300): need the CSR modules in the model and machine registers.
- Zbb, Zbkb, Zbs: add `SAIL_MODULES`, new `Instr` forms, `BinOp`s.
- `ecall`, atomics: new outcomes in `next` and trap modelling.
- Unaligned accesses: drop the alignment check in `load`/`store` and re-prove `Rel.mem` steps.
- Indexed stores: `Write` with a symbolic index (plan S5 recipe).

- F3 compliance: zesislar has no nextUint64-vs-Sail statement; the Sail side `sailNext`
  (item decode + `rlp_decode_uint64`) was defined in `Compliance/F3.lean` and needs review.
- F6 `Post` states only the error bytes on both error paths (not the copied constant) and
  leaves the scratch word's final value unstated.
