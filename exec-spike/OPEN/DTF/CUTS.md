# DTF `rlp_decode.decodeTxFields`: cut points, assertions, budgets (S7 step 3)

## Cut points (162)

- The map's 153 (`zmap show f_8000050c`, join cuts on): entry, 50 loop heads (byte loops of the
  field helpers, one block each), 87 call return sites, 15 join cuts.
- The five jump-table targets (`.jumpInd` leaves from `0x80000574` must end at a cut).
- Three hand-placed cuts (ledger `assertion` items):
  - `0x80000574`, the jump-table load: the executor reads rodata only at literal addresses, so the
    table word `0x80110050 + 8·t` is made region 4 (8 read-only bytes);
  - `0x80002138`, the store of a versioned hash into the `txHashList` buffer (`a0` = slot, 32 B);
  - `0x80002434`, the store of an `AuthorizationTuple` into the `txAuthList` buffer (0x90 B).
  The executor stores only at constant offsets of a region.

Runs: 162 `sym_run`s, 486 leaves, all evaluate (fuel 300); `Runs.lean` builds in 218 s (all runs
together; the 60 s per-run limit of the plan's last assumption is not approached, so no further
hand-placed cut was needed).

## Callee summaries for `decodeItem` (measured, not used)

`runWith` with F3's `decodeItem` summary from `0x80000588`: with the map's return sites kept it
passes the first call and stops at the next cut (1 leaf); with the return sites of the legacy arm's
first ten calls removed it returns `none`. Every field reuses the outcome slot `S-0x90`, and the
`rest` registers after one call hold `rest + consumed` read from that slot, so the second call's
state mentions the bytes the call writes (`CallRec.okB` fails). Summaries would need fresh symbolic
writes instead of a havocked `mem0` (a change to `Sym/Summary.lean` and `runWith_sound`); the
return-site cuts stay.

## Shapes (`Regions.lean`, generated by `shape.py`)

`python3 OPEN/DTF/shape.py <elf> <cut pcs> --lean` prints the `table` rows: a forward analysis of
the instructions (abstract values: entry-`sp`-relative, result/allocator-object-relative, the vtable
word, payload pointers tagged with the number `k` of top-level items consumed, `rest` lengths,
`decodeItem` consumed lengths; frame slots at 8-byte granularity; calls clobber the ABI registers
and the callee's outcome/rest/header ranges). Per cut: the registers/slots that hold pointers (the
cut's `SState` overrides and known facts, stated by `ShapeOk`), the arms reaching it, where the
latest `rest` slice is (`RestOk`), and for a return site the same at the call instruction.

## Assertions (`Cuts.lean`)

`PlainA` = pc, `Common`, `ShapeOk`, `ArmOk`, `RestOk`, `Extra`; `RetA` = call-site predicate at the
call machine and the callee's `Post`; `ACut` = the disjunction (only `0x80002a6c` is both a return
site and a jump target). `Extra`: `0x80000574` the table address, `0x80002138`/`0x80002434` the
buffer slot (RAM, present, from `Priv`), `0x800011f8` the written result (`Done`).

### Open assertion items (not yet stated)

1. Field values: the decoded scalar fields held in registers/frame slots (u64 in one register,
   u128 in two, u256 in four limbs; spilled at `S-0x238..`, `S-0x248..`, `S-0x268..`, …), the
   `to` address copy at `S-0x238` and its tag `S-0x258`, the `data`/list slices. Needed by the
   success write `0x80002dc4 → 0x800011f8` (`Done`'s success disjunct) and by every leaf that
   carries a field value forward.
2. Per-field checks before the current item (the reference parser's `isList`/length tests) — the
   prefix of `body t` that has succeeded; with 1, `RestOk` becomes "the first `k` fields of `body t`
   parse to the held values".
3. List loops: the `txHashList` buffer `{ptr, len, cap}` at `S-0x118` and its bytes; the
   `txAuthList` buffer at `S-0x330`/`S-0x338`/`S-0x318` and the tuples so far; the inner cursors
   (`s7`/`s6`, `S-0x300`/`S-0x308`); the list bytes left (budget term) must be tied to the list
   payload.
4. Byte loops: cursor/end inside the current item's payload and the accumulator so far (budget
   term `20·(end - cur)` needs `end - cur ≤ 32`).
5. Callee indices beyond the heap: F1/F4's list bytes, TX's input. (`IdxOk` now states the
   callee's `Pre` and, for the allocator, F1, F4 and TX, `Live σ m x.1 X`.)
6. For the TX return sites: `Live` after TX needs the returned/leaked blocks to come from
   `Priv g.L`; TX's `OutcomeImage` states `L' ~ g.L ++ blocks` and `Heap L' m'` only. Either
   derive it (`arena_split` at the entry and at `m'`, blocks disjoint from `g.L` by `live_ok`) or
   weaken `Live`'s carve condition.

## Budgets

`K + 256·(rest length) + inner`; `K` from `OPEN/DTF` budget computation (longest path over the cut
graph, back edges `0x80002138→0x800020ac` and `0x80002434→0x800024d0` and the byte-loop self edges
removed; callee bounds F2 75, F1 197, F4 194, memcpy 3, alloc 53, free 42, remap 9, TX `txBound`;
640 per entry into a byte loop). Back-edge slack: hash loop needs 320 ≤ 256·33 (an item is ≥ 33
bytes), authorization loop 4200 ≤ 256·27 (a tuple is ≥ 27 bytes). Entry budget 34,359,750,421
(`txBound` = 34,359,738,792 of it).
